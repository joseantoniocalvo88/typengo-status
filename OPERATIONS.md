# Independent status monitor (deployment template)
Export a minimal public status-only repository with node tooling/status/export.mjs /path/to/new-directory. The export contains the static site, collector and a GitHub Actions workflow. GitHub Pages supports free hosting for a public repository. Never expose the private CMS repository. Create a separate status-only public repository, upload these files, use Settings > Pages > GitHub Actions, then trigger the workflow manually and verify the historical sample and page. The template defaults to the preview health endpoint. Set TYPENGO_HEALTH_URL to https://typengo.com/api/health only after production release. A target switch resets history. One HTTP request every 15 minutes, no database request, bounded history (2016 samples, approximately 21 days if scheduling is regular). The previous history artifact is retained for seven days. If scheduled runs stop longer than artifact retention, history restarts. Delayed/missing samples are not uptime; the page labels data stale after 45 minutes. The workflow does not make calls to business sites or AI. It has not been installed or scheduled yet. Optional custom DNS and alerting are separate activation tasks. See https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages and https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows.
